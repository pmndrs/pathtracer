# Decisions

Settled calls. Each has a date, what was decided, and why. Change one only with a new entry that supersedes it.
Open questions live in TASKS.md, phrased with a suggestion, pros/cons and the A/B that would settle them.

| D22 | 2026-11-14 | Light selection default is `pbrt`: what pbrt-v4's default `bvh` sampler does (each infinite light 1/(nInfinite+1), the area lights together the remaining share; Mitsuba's uniform emitter weights are the same idea). | D23 | 2026-11-15 | Tier 1 gate = class A scenes only (thick dielectric + volume against Mitsuba, thin smooth transmission, black-base ior, grey metals, emissive strength, anisotropic metals). | D24 | 2026-11-15 | Library default layering: `layering: 'albedo'` with `albedoBase: 'internal'`. The stochastic walk stays the reference-mode setting; OpenPBR's albedo formula stays a setting. | P2.21 A/B: internal +0.4-3.7% vs references, OpenPBR albedo +5-11%, walk within 0.8% but costlier |
| D25 | 2026-11-15 | Wide BVH: choose the format per scene (BVH4 folded on Sponza-class, CWBVH8 on Bistro-class) with the folded decode, until the RTX 3060 runs; then fix one default. | X1 quiet M5 numbers; the 3060 is the other gate device |
| D26 | 2026-11-15 | Kernel size: measure DXC compile time on the RTX 3060 (W10) before adding more material features to the megakernel. If it is slow, split rare lobes into specialised kernels or pull the P3 wavefront split forward. | layered/fuzz/film/aniso/coated-metal kernels are 51-55 KB, past the ~50 KB DXC guideline; cost unmeasured |
| D27 | 2026-11-15 | Speed first for cutouts: the `realtime` and `preview` modes default to `alphaPolicy: 'opaqueSecondary'` (cutouts solid for shadow rays and indirect hits; ~20-23% of trace time on a foliage scene, est. 6.5-8 ms per sample at 1080p). `reference` stays `exact` (the gates). The darkness this costs (3-17% on card scenes) is worked down separately (R2b). | maintainer: "speed is most important; we can work out the darkness but getting back 6.5-8 ms will be harder"; quiet pass 20261115-1714 R2 table |
| D28 | 2026-11-14 | VkNRC is built natively under `.cache/native/vknrc` as the native NRC baseline (N6.1), an explicit exception to "never build clones" like pbrt-v4 and Mitsuba. Timings and images only; local patches (timestamps, fixed camera, PFM dump) stay in `.cache`, nothing of it is committed or redistributed. | maintainer call; native vs web is the question the track answers |
| D29 | 2026-11-14 | Research track N follows VkNRC's design closely (kernel layout, record formats, pass graph, constants, test order) as an experiment. Asking the author for a licence is not needed now; revisit if code from it would ever ship. | maintainer call; VkNRC has no licence (default copyright, public repo here), and GLSL + NV coop matrix to WGSL subgroup-matrix is a rewrite anyway |
