## Phase 1 results on the Mac

## Streaming a building, courtyard and neighboring building

**Current behavior.** The network trains online and the image can reset while keeping its weights. Every query normalizes its world position against one bounding box supplied at cache creation and clamps it to [−1, 1]. A courtyard outside that box loses positional detail along the clamped axes. Expanding the box changes the encoded positions of surfaces the network already learned. The scene copy also rebuilds on change. Its GPU buffers can be rewritten when the data fits or replaced and rebound when it grows. The bench does not implement a chunk loader or region-aware trust for the network. [NRC encoding and lifecycle](../../bench/nrc/cache.ts) · [Scene copy](../../packages/raytracer/src/scene/scene-copy.ts) · [GPU upload](../../packages/raytracer/src/scene/gpu.ts)

**First prototype.** For a bounded campus, supply a fixed campus box before loading the first building. Keep that transform and the trained weights as the camera moves. Test whether a single compact MLP retains enough local detail across the campus. Track coverage in stable world cells, since an MLP returns an RGB prediction even for a place it has never seen. When courtyard geometry becomes ray-visible, trace low-confidence hits to completion and collect training suffixes there. Rays through a doorway or in a mirror should warm the courtyard before the camera crosses the threshold. Give those rays access to resident geometry or an explicit lighting proxy. A cache cannot reconstruct a newly placed occluder that the tracer has never seen. [Online NRC](https://research.nvidia.com/publication/2021-06_real-time-neural-radiance-caching-path-tracing) · [Hash validity experiment](#phase-1-results-on-the-mac)

**Larger worlds and revisits.** If a campus-wide encoding loses fine detail or training in building B degrades a revisit to A, compare a shared decoder and streamable local feature grids with one small network checkpoint per region. Local coordinates and a persistent region ID preserve feature addresses across origin rebasing. Save a region's features or weights together with its coordinate transform, encoding version, and geometry/lighting revision. Checkpoint optimizer state as well for an exact training resume. Keep overlap at doors and test continuity across the boundary. Training a shared decoder can change the meaning of saved features, so freeze or version it for that comparison. [Learned multiresolution features](https://nvlabs.github.io/instant-ngp/) · [On-surface caching](https://doi.org/10.1145/3675382)

**Streaming test.** Use the same A → courtyard → B → A route for three runs. First keep all geometry resident, then stream regions under unchanged lighting, then load a wall or bright emitter just outside the doorway. Mark affected cached transport stale on both sides of the door and use traced light while it recovers. Compare doorway and mirror crops against an all-resident high-spp reference, including frame one and frames to recover on arrival and revisit. Record load/upload stalls, cache memory, training cost, and lost detail in A. This exercises actual scene mutations in addition to the camera-only gallery cut.

## Consumer contract and checkout

Before connecting either GI or reflections, add an isolated Lambert receiver under a constant sky, then one area light, then one colored bounce wall. In the sky-only case the full result is albedo × sky radiance and a strictly indirect term is zero. The megakernel's cached suffix can contain a complementary BSDF-sampled direct-light contribution because the preceding next-event estimate is MIS-weighted. L2 hit shading already evaluates a full direct-light sample. Either align the two estimators or produce a strictly indirect consumer target. ## Cross-platform WebNN experiment

The `nrc-webnn` bench page compiles a five-hidden-layer fp16 graph, publishes changing weights through WebGPU and verifies each RGB channel and the padding. With `repeats=20` it runs three untimed warm-ups and reports graph compilation time and wall-clock p50/p95 for a complete **batch**. The timed interval starts with encoded features and six weight matrices already in GPU buffers and ends after exported predictions have been copied to a GPU buffer and the queue has completed. It includes all seven input transfers, graph dispatch and output transfer. Readback and fixture setup are outside the interval. This is a conservative per-batch weight refresh. A renderer usually can amortize one weight publication across many batches. [Experiment source](../../research/probes/nrc-webnn.html)

**Observed on the Mac.** At 4,096 rows all four weight snapshots and the last timed output passed on both requested device types. Per-input drains took 10.8/12.4 ms (p50/p95) on the GPU request and 9.8/10.5 ms on the NPU request. Grouping the handoff wait gave 9.9/12.6 ms and 8.0/8.3 ms respectively. These headless, background-app results support reducing handoff overhead and do not establish hardware placement or a renderer speedup. The earlier three-channel and 16,384-row failures remain useful diagnostic controls. [Initial probe observations](../../research/notes/13-radiance-cache.md)

**Windows run card.** From the pathtracer root in PowerShell, run the correctness sweep first. A missing NPU or export operation is a capability result. Repeat on an NPU-equipped machine if available. Set `--chrome` to the Edge executable to test Edge separately when installed. Record the browser version, flags, WebGPU adapter and enabled backend for each run. The NPU request describes the WebNN context; `--gpu nvidia` selects the renderer adapter.

```powershell
$env:PT_CHROME_FLAGS = '--enable-features=WebMachineLearningNeuralNetwork'
foreach ($rows in 64,4096,16384) {
  node bench/runner/run.ts --page nrc-webnn --gpu nvidia --args rows=$rows channels=4 handoff=drain --ab device=gpu,npu
}
# Time passing device/shape pairs. Repeat with device=npu if correctness passed there.
node bench/runner/run.ts --page nrc-webnn --gpu nvidia --headed --repeat 3 --args rows=4096 channels=4 device=gpu repeats=20 --ab handoff=drain,grouped
node bench/runner/run.ts --page mlp-timing --gpu nvidia --headed --repeat 3 --args precision=f16 size=64 --ab infer=portable,tiled
```

For the Mac, run the same pages with `--gpu apple` and set `PT_CHROME_FLAGS=--enable-features=WebMachineLearningNeuralNetwork,WebNNCoreMLExplicitGPUOrNPU` for the tested Chrome build. The standalone probe opens directly for the four snapshots. Add `?rows=4096&device=gpu&handoff=grouped&repeats=20` for the timed batch. The runner saves the configuration, results and timings in its normal JSON/CSV output.

**Decision after the sweep.** The WGSL microbench above gives kernel-only context on a 4,096-row image workload. For a backend decision, capture real NRC records, query counts and an EMA weight snapshot from the fixed renderer. Replay the same records through portable WGSL and passing WebNN shapes, compare predictions with the CPU oracle and reject stale snapshots. Measure feature packing, useful/padded rows, snapshot publication, dispatch, waits and scatter. Compare the whole `nrc-pipeline-study` frame on the same machine, including training, denoising and upscaling. Record cold build separately. ## Comparison protocol

At each applicable phase save linear PFM A/Bs against the same high-spp reference and export both a full frame and a fixed glossy crop. Compare at 1 and 256 frames, cold start, camera cut, motion and after a lighting edit. Report signed HDR bias, relMSE, FLIP and temporal flicker before and after denoising. Compare GPU memory, ray/query counts and quiet windowed p50/p95 frame time on each platform. Change one feature per comparison, then repeat the winners together. A quality win on a static diffuse scene alone does not qualify a reflections backend. [NRC study](../../bench/pages/nrc-study.ts) · [Pipeline study](../../bench/pages/nrc-pipeline-study.ts)
