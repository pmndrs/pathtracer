`@pmndrs/raytracer` traces rays against a triangle BVH on WebGPU. Rays go in, hits come out. What you do with a hit is up to you.

Use it when your renderer already exists and needs rays for one job:

- **Reflections**: trace from the G-buffer, shade the hit with your own lighting or with `rtShade`.
- **Shadows**: one visibility ray per light sample.
- **Ambient occlusion**: a few short visibility rays per pixel.
- **GI probes and caches**: rays from probe positions, or from surfaces, with radiance at the hit.
- **Baking**: lightmaps or probe data, offline or at load time.

If you want a rendered image instead, use [`@pmndrs/pathtracer`](/getting-started/choosing-a-package), which is built on this package.

## Three ways to trace

| Way | What it is | Use it when |
| --- | --- | --- |
| [Inline WGSL](/raytracer/inline-wgsl) | `rtModuleWgsl` returns WGSL functions (`rtVisible`, `rtClosest`, `rtSurface`) to paste into your own compute shader. | You already have a kernel per pixel or per probe and want to trace from inside it. |
| [Batch tracer](/raytracer/batch-tracer) | `RtBatchTracer` traces a GPU buffer of rays into a GPU buffer of results. | Rays are generated by one pass and consumed by another, or the count lives on the GPU. |
| [Interval queries](/raytracer/interval-queries) (experimental) | Closest hit and visibility inside a half-open range `(t0, t1]`, inline or batched. | Radiance cascades and other probe tracing that splits a ray into segments. |

All three run the same WGSL walk over the same buffers, so a scene uploaded once serves all of them.

## What it is built on

- [`@pmndrs/bvh`](https://github.com/pmndrs/bvh) builds the trees and provides the WGSL walk. Its WGSL names start with `bvh`; everything this package adds starts with `rt`, `Rt` or `RT_`.
- [`@pmndrs/downsampler`](https://github.com/pmndrs/downsampler) fills texture mip levels on the GPU when a scene has textures.

Both are regular dependencies; [Installation](/getting-started/installation) has the bundler note for bvh's workers.

## The pieces

A scene on the GPU has two halves:

- **The trace buffers** (bvh): nodes, triangles and the top level. This is all `rtVisible` and `rtClosest` need.
- **The scene copy**: instance transforms, vertex attributes, materials, lights and textures. `rtSurface`, `rtMaterial`, light sampling and `rtShade` read it.

`buildGpuScene` builds and uploads both from one input. See [Your first render](/getting-started/your-first-render) and [Loading glTF](/getting-started/loading-gltf) for how to get there from triangles or a `.glb`.

```ts
import { buildGpuScene, detectCaps, requestDeviceForCaps } from '@pmndrs/raytracer';

const adapter = await navigator.gpu.requestAdapter();
const { device, caps } = await requestDeviceForCaps(adapter!, detectCaps(adapter!));
const scene = await buildGpuScene(device, input);
// scene.trace: bvh buffers. scene.buffers: the scene copy. scene.format, scene.packing: what kernels compile for.
```

## Examples

- [Rays from your own shader](https://pmndrs.github.io/pathtracer/examples/raytracer/hits/): `rtClosest`, `rtVisible` and `rtSurface` in your own compute shader, with the shadow, reflection and AO rays a raster pass cannot trace.
- [Ambient occlusion](https://pmndrs.github.io/pathtracer/examples/raytracer/ao/): short `rtVisible` rays from each pixel.
- [Batch shadow rays](https://pmndrs.github.io/pathtracer/examples/raytracer/batch/): `RtBatchTracer` over a buffer of rays.
- [One-bounce shading](https://pmndrs.github.io/pathtracer/examples/raytracer/shade/): `rtShade` lighting the hits.
