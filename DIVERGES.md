# Divergences

Where we deliberately differ from a source we built on (paper, sibling package, competitor, native renderer), and
why, so each one can be revisited later. One row per divergence. Kinds: **platform** (browser/driver/WGSL limit),
**perf** (measured speed choice), **licence**, **simplification** (do it properly later), **bug-workaround**.

| V6 | 2026-11-13 | NVlabs FLIP (via Denoiser's port) | LDR-FLIP skips the sRGB decode (our tonemap output is already display-linear), so on 8-bit-style input it reads about +0.014 mean (0.1737 vs 0.1597 on NVlabs' pair), which is why the metric is always fed tonemapped radiance, never encoded PNGs; `srgbDecode` switches the decode on for validation only. Separable kernels and clamped borders are NOT a departure: NVlabs flip 1.7 does the same, and with the decode on our map matches theirs to mean 2.6e-8, max pixel 1.6e-5 (float32/platform). HDR-FLIP (P0.14) follows `FLIP.h` (commit d3ab02a): mean 0.283547 and exposures -12.5423..0.9427 x14 identical to the pip package, max pixel 9e-6; its ACES is the 0.6-pre-exposure-cancelled form, not our display ACES, and it takes no EV. Ours add: NaN/negative input counts as 0, per-exposure maps run on worker_threads (bit-identical to serial). AgX is the "minimal AgX" approximation | simplification | validated 2026-11-13 against NVlabs images + `flip-evaluator` 1.7 (macOS arm64; their README says Windows references differ from other OSes at the 1e-6 level) |

| V17 | 2026-11-13 | bench runner (extends V5) | `readReport` treats a DevTools `Runtime.evaluate` timeout as "page busy" and keeps polling until the run's own deadline (before: the run failed after 30 s). tgpt's timed pass is one synchronous loop with no await between snapshots, minutes long on Sponza | bug-workaround | the adapters yield to the event loop without a GPU sync, or the runner gets a heartbeat |
| V18 | 2026-11-13 | P0.9 error metric | relMSE is taken against ONE 4096 spp reference and the reference's own noise is not subtracted (Sponza: Mitsuba alone about 2e-3 of the error; pbrt-vs-Mitsuba 4.1e-3). | V19 | 2026-11-13 | Sponza on web competitors | sun = glTF `KHR_lights_punctual` directional light (lux 1:1, delta light, V15), sky = uniform float equirect; no per-renderer sun or bounce adjustment was needed: image means match pbrt to <0.05% and Mitsuba to -0.2% (V10 mapping holds with maxDepth 8) | none needed | a sun with angular radius, or a textured Sponza |
| V20 | 2026-11-13 | STBN (Wolfe et al. 2022) / FAST (Donnelly et al. 2024) | Our `st` blue noise is void-and-cluster on a 3D torus with a summed ("separate") spatial Gaussian inside a slice + temporal Gaussian along a pixel's time axis (σ 1.5 / 1.5, weight 1), ranks over the whole volume; vec2 is two independent scalar runs, not STBN's vector-valued optimisation; no filter-adapted (FAST) loss. It did not beat a 2D texture + golden-ratio shift under accumulation (tools/bluenoise/REPORT.md) | simplification | P4 A/B through our TAA/OIDN path, or a FAST-style loss |
| V21 | 2026-11-13 | Georgiev & Fajardo 2016 (blue-noise dithered sampling) | `gf` vec2 textures: greedy swaps only (no annealing), random global pairs, stratified shuffled start (marginals stay exact permutations), 200 proposals/pixel, plain (non-toroidal) sample distance, image kernel cut at 3σ | simplification / perf | the 2D-integrand A/B gains more from a better optimiser, or a joint vec2 for `st` is needed |
| V22 | 2026-11-13 | mutracer `readPixels('hdr')` | The adapter multiplies the read-back RGB by its alpha (coverage): mutracer returns straight colour, i.e. the mean over the samples that hit something, so silhouette pixels against an empty background (Cornell box rim) read fully lit while the references average the black misses in. Opaque pixels and pixels with a visible environment have alpha 1 and are bit-identical. This one switch was the whole "mutracer stops converging on Cornell" plateau (relMSE at 4096 spp 5.7e-4 to 4.8e-5). Separately mutracer reads +0.13% on the albedo-0.5 diffuse furnace (0.50063; unchanged by candidates, sampler, dispersion, bounces, env map size), a property we leave as is | platform (API semantics) | upstream returns associated colour, or we find the +0.13% |

| V23 | 2026-11-13 | Spec §2 `rtClosest(ray, mask, cone?)` | Two WGSL functions: `rtClosest(ray, mask)` and `rtClosestCone(ray, mask, cone)` (adds `coneWidth` at the hit); the batch kernel has a `cones` setting | platform (WGSL has no optional parameters) | a consumer needs cone-only overloads generated per call site |
| V24 | 2026-11-13 | Spec §2 `rtSurface(hit, SurfaceMask)` | `rtSurface(hit, ray, want)`: the ray is needed for the default world position (`origin + t·dir`); barycentric positions are opt-in (`positions: true`, +12 B/vertex). No tangent and no material parameters yet; its data is a small stand-in table (`buildSurfaceTable`), not the D4 scene copy | simplification | scene copy (D4) and L2 land |
| V25 | 2026-11-13 | bvh `bvhTraceAny` / batch any-hit (`true`/1 = blocked) | `rtVisible` and the `visible` batch return `true`/1 = **visible** (nothing blocks), the spec's L0 "VIS" reading | simplification (naming) | consumers find the inversion confusing |
| V26 | 2026-11-13 | bvh `TraceBatchKernel` / `batchKernelWgsl` | Own batch kernel (`rtBatch`) instead of bvh's: count and capacity in a uniform (bvh uses `arrayLength`), GPU-side count + one-thread args kernel for indirect dispatch, SoA rays, cones, 2D grid past 65535 workgroups. | V27 | 2026-11-13 | P1 brief "same triangle, t within 1e-5 relative" | bvh's CPU walk (`createCpuTracer`, `CpuSceneBvh`) does f64 math on the f32 scene; the GPU does f32. trace-core therefore classifies, counts and reports, but does not fail: (a) a different triangle at the same t next to an edge, or on a coplanar surface (tie); (b) hit-vs-miss where the ray only *touches* a convex edge/corner or an open boundary edge (grazing); (c) t past 1e-5 relative whose gap along the normal is within 1e-5 of the coordinates' magnitude (tPosition).
